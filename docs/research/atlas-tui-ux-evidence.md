# Research: Making Atlas more user-friendly, powerful, and interactive

Research snapshot: August 2026.

- [HIGH | Primary-local] Scope context: small Windows-first Python/Textual app over Google Shared Drive project folders. Local lock resolves Textual 8.2.8.
- [HIGH | Primary-local] Research handling: no repository code or private project data was sent to external services.

## Executive finding

- [HIGH | Primary] **Best near-term return:** make scans non-blocking, add keyed filter/sort, show selected-project detail, make actions contextual, and preserve plan-before-apply safety. Textual already supplies workers, loading states, keyed/sortable `DataTable`, focus-scoped bindings, dynamic action checks, responsive breakpoints, and notifications. [Workers](https://textual.textualize.io/guide/workers/) · [DataTable](https://textual.textualize.io/widgets/data_table/) · [Input and bindings](https://textual.textualize.io/guide/input/) · [App breakpoints](https://textual.textualize.io/api/app/#textual.app.App.HORIZONTAL_BREAKPOINTS)
- [HIGH | Primary] **Do not start with a broad customization system or universal undo.** K9s labels configuration, hotkeys, and custom views as changing or experimental; lazygit limits undo/redo to commit operations and excludes working-tree changes. [K9s configuration and custom views](https://github.com/derailed/k9s/blob/master/README.md#k9s-configuration) · [lazygit global keybindings](https://github.com/jesseduffield/lazygit/blob/master/docs/keybindings/Keybindings_en.md#global-keybindings)
- [HIGH | Primary] **Do not preload project files on the shared drive.** Yazi explicitly recommends disabling previewers and preloaders on network files because previewing can download remote content. Atlas should derive the first detail view from its existing shallow inventory, then load deeper detail only on explicit request. [Yazi remote-folder preview guidance](https://yazi-rs.github.io/docs/tips/#folder-previewer) · [Yazi performance guidance](https://yazi-rs.github.io/docs/tips/#make-yazi-even-faster)
- [HIGH | Primary] **Keep CLI parity as accessibility and recovery path.** Textual's screen-reader accessibility issue remains open, with no milestone or implementation attached. Keyboard completeness helps, but does not establish screen-reader accessibility. [Textual accessibility issue #2425](https://github.com/Textualize/textual/issues/2425)

## Findings

### Command palette, contextual keybindings, and help

- [HIGH | Primary] Textual's palette is enabled by default, fuzzy-searches commands, supports app and screen commands, and supports custom providers whose startup work can run in a thread. Screen commands are naturally contextual. [Textual command palette](https://textual.textualize.io/guide/command_palette/)
- [HIGH | Primary] `Footer` displays bindings available to the currently focused widget and makes them clickable. Bindings can be hidden from the footer or given custom display text. [Textual Footer](https://textual.textualize.io/widgets/footer/)
- [HIGH | Primary] Textual resolves bindings from the focused widget upward through the document object model. This supports moving project-only commands off the app and onto the project table/screen. [Textual binding resolution](https://textual.textualize.io/guide/input/#bindings)
- [HIGH | Primary] `check_action` can disable or hide unavailable actions; disabled footer entries are visually muted. This is preferable to actions that silently return when no drive or project is selected. [Textual dynamic actions](https://textual.textualize.io/guide/actions/#dynamic-actions)
- [HIGH | Primary] Current Textual exposes a built-in keys panel via `action_show_help_panel`; `BINDING_GROUP_TITLE` and `HELP` support structured contextual help. [Textual App API](https://textual.textualize.io/api/app/#textual.app.App.action_show_help_panel) · [DOM node help metadata](https://textual.textualize.io/api/dom_node/#textual.dom.DOMNode.BINDING_GROUP_TITLE)
- [HIGH | Primary] Mature TUIs retain a universal help key even when they expose direct commands: lazygit uses `?` for its keybindings menu; K9s uses `?` for active mnemonics/help; Yazi uses `F1` or `~`. [lazygit keybindings](https://github.com/jesseduffield/lazygit/blob/master/docs/keybindings/Keybindings_en.md#global-keybindings) · [K9s keybindings](https://github.com/derailed/k9s/blob/master/README.md#key-bindings) · [Yazi quick start](https://yazi-rs.github.io/docs/quick-start/)
- [MEDIUM | Primary-derived] For Atlas, palette should be an alternate route, not the sole route. Direct keys optimize repeated use; palette/help exposes infrequent actions and teaches terminology. Evidence comes from Textual's simultaneous footer and palette, plus mature TUIs retaining both direct keys and searchable/modal command surfaces.

### Table filtering and sorting

- [HIGH | Primary] `DataTable.sort` supports one or several columns, custom key functions, and reverse order. `HeaderSelected` allows click-to-sort without custom mouse coordinate handling. [DataTable sorting and messages](https://textual.textualize.io/widgets/data_table/#sorting)
- [HIGH | Primary] Stable row keys remain valid through sorting and row deletion. Coordinates do not. Atlas should map selection, marks, and detail to project keys, never list indices. [DataTable keys](https://textual.textualize.io/widgets/data_table/#keys)
- [HIGH | Primary] `DataTable` does not provide a filter API. Official docs describe application-owned repopulation after searching/filtering. For a studio-sized project list, filtering the canonical in-memory rows and repopulating is simpler than building a custom virtual table. [DataTable overview](https://textual.textualize.io/widgets/data_table/)
- [HIGH | Primary] Filtering and sorting are core interactions in K9s, lazygit, Yazi, and VisiData. K9s supports regex, inverse regex, label, and fuzzy filtering plus named sorts; lazygit uses `/` in list views; Yazi separates filter, find, search, and sort; VisiData supports selected subsets and multi-column sorts. [K9s keybindings](https://github.com/derailed/k9s/blob/master/README.md#key-bindings) · [lazygit list navigation](https://github.com/jesseduffield/lazygit/blob/master/docs/keybindings/Keybindings_en.md#list-panel-navigation) · [Yazi quick start](https://yazi-rs.github.io/docs/quick-start/#filter-files) · [VisiData rows](https://www.visidata.org/docs/rows/)
- [MEDIUM | Primary-derived] Atlas does not need regex or query-language filtering first. Case-insensitive substring matching across project name and status, plus quick status chips/toggles, covers the likely small-list use case with lower error cost.

### Master-detail and project drilldown

- [HIGH | Primary] Textual's row-highlight event supplies a row key suitable for synchronizing a detail pane as keyboard or mouse selection changes. [DataTable `RowHighlighted`](https://textual.textualize.io/widgets/data_table/#textual.widgets._data_table.DataTable.RowHighlighted)
- [HIGH | Primary] Textual can apply width and height breakpoint classes automatically, allowing the same screen to switch from side-by-side to stacked or drilldown layouts. [Textual app breakpoints](https://textual.textualize.io/api/app/#textual.app.App.HORIZONTAL_BREAKPOINTS)
- [HIGH | Primary] Lazygit defaults to a side panel plus main view and changes split direction when width is insufficient. Its config explicitly defines `flexible` as horizontal when wide enough and vertical otherwise. [lazygit `mainPanelSplitMode`](https://github.com/jesseduffield/lazygit/blob/master/docs/Config.md?plain=1)
- [HIGH | Primary] K9s keeps tables as the navigational surface and exposes selected-resource YAML, logs, describe, details, relationships, and full-screen views as drilldowns. [K9s keybindings](https://github.com/derailed/k9s/blob/master/README.md#key-bindings)
- [MEDIUM | Primary-derived] Atlas detail should explain the selected row before asking users to mutate it: overall status, missing control-plane items, drift, relocations, sweeps, unfiled items, and the exact conform plan. Full folder browsing belongs behind an explicit detail action.

### Async workers, loading, and progress

- [HIGH | Primary] Textual warns that any operation taking more than a few milliseconds can block message processing. Workers are the supported concurrency mechanism. [Textual workers](https://textual.textualize.io/guide/workers/#concurrency)
- [HIGH | Primary] `exclusive=True` cancels older workers so stale responses do not overwrite newer intent. This directly fits repeated refresh, drive switching, and live filtering that triggers expensive detail work. [Exclusive workers](https://textual.textualize.io/guide/workers/#workers_1)
- [HIGH | Primary] Blocking filesystem APIs require thread workers. Textual UI methods are generally not thread-safe; publish results with `call_from_thread` or thread-safe `post_message`. [Thread workers](https://textual.textualize.io/guide/workers/#thread-workers)
- [HIGH | Primary] Thread workers cannot be cancelled like coroutines. They must check cancellation cooperatively. Atlas should also attach a generation/drive ID to results so late scans are discarded. [Thread worker cancellation](https://textual.textualize.io/guide/workers/#thread-workers)
- [HIGH | Primary] Every widget has a `loading` reactive that temporarily substitutes a built-in `LoadingIndicator`. Use indeterminate loading for scans; use `ProgressBar` only when the plan exposes a meaningful total. [Widget loading](https://textual.textualize.io/guide/widgets/#loading-indicator) · [ProgressBar](https://textual.textualize.io/widgets/progress_bar/)
- [HIGH | Primary] Yazi's first-party guidance says network-file previews and preloaders can download content and should be disabled. This is directly relevant to Google Drive hydration behavior. [Yazi performance guidance](https://yazi-rs.github.io/docs/tips/#make-yazi-even-faster)

### Notifications, errors, and operation status

- [HIGH | Primary] Textual `notify` supports information, warning, and error severities, titles, markup, and timeout. Default notification lifetime is five seconds. [Toast and notifications](https://textual.textualize.io/widgets/toast/) · [App notification timeout](https://textual.textualize.io/api/app/#textual.app.App.NOTIFICATION_TIMEOUT)
- [HIGH | Primary] K9s pairs transient UI with discoverable state/log locations through `k9s info`, and warns that some custom-view errors appear only in logs. The latter is a negative pattern for Atlas: actionable user errors should not be log-only. [K9s logs](https://github.com/derailed/k9s/blob/master/README.md#logs-and-debug-logs) · [K9s custom-view warning](https://github.com/derailed/k9s/blob/master/README.md#custom-views)
- [MEDIUM | Primary-derived] Use toasts only for compact success and non-blocking notices. Keep failed operation, affected project, safe retry, and partial-result details visible until superseded or dismissed. Retain machine-oriented logs for diagnosis.
- [MEDIUM | Primary-derived] Batch result UI should report succeeded, skipped, conflicted, and failed counts separately. “Completed” must not conceal partial application.

### Preview safety and undo

- [HIGH | Primary] K9s supports a read-only startup mode that disables modification commands. Its plugins separately declare confirmation and dangerous/read-only behavior. [K9s read-only mode](https://github.com/derailed/k9s/blob/master/README.md#the-command-line) · [K9s plugin safety fields](https://github.com/derailed/k9s/blob/master/README.md#plugins)
- [HIGH | Primary] K9s confirms delete with Tab and Enter but documents force-kill as having no confirmation. This is a useful counterexample: expert speed can conflict with recoverability. Atlas should not copy unconfirmed destructive shortcuts. [K9s delete vs kill](https://github.com/derailed/k9s/blob/master/README.md#key-bindings)
- [HIGH | Primary] Lazygit's global undo/redo is explicitly limited to commit operations and excludes working-tree changes. Even a mature domain TUI avoids claiming universal undo where the domain cannot guarantee it. [lazygit undo/redo](https://github.com/jesseduffield/lazygit/blob/master/docs/keybindings/Keybindings_en.md#global-keybindings)
- [HIGH | Primary] Lazygit exposes warnings for amend, discard, stash, editor reword, and worktree switching, while allowing advanced users to suppress individual warnings. [lazygit warning configuration](https://github.com/jesseduffield/lazygit/blob/master/docs/Config.md?plain=1)
- [MEDIUM | Primary-derived] Atlas should treat an immutable plan as the primary safety primitive: build plan, show paths and counts, confirm, apply with precondition checks, report each result, append log. Add true undo only when the inverse is provably safe against intervening filesystem changes.
- [MEDIUM | Primary-derived] Offer a temporary read-only session flag before batch mutation. It is cheaper and safer than a broad permissions/configuration system.

### Mouse, keyboard, and accessibility

- [HIGH | Primary] `DataTable` supports arrow keys, paging, Home/End, Enter selection, hover, and click selection. Textual focus can move with Tab/Shift+Tab, and the focused state is styleable. [DataTable cursors](https://textual.textualize.io/widgets/data_table/#cursors) · [Textual focus](https://textual.textualize.io/guide/input/#input-focus)
- [HIGH | Primary] Textual recommends click events over raw mouse down/up because future pointing devices may not have those states. Atlas should use widget messages and bindings instead of manual coordinate logic. [Textual click guidance](https://textual.textualize.io/guide/input/#click-events)
- [HIGH | Primary] Textual warns not all key combinations are supported and some are intercepted by the operating system. `textual keys` is the official diagnostic. [Textual key warning](https://textual.textualize.io/guide/input/#key)
- [HIGH | Primary] Lazygit documents that capturing mouse events makes terminal text selection harder. K9s leaves mouse support disabled by default. Mouse must remain additive, never required. [lazygit `mouseEvents`](https://github.com/jesseduffield/lazygit/blob/master/docs/Config.md?plain=1) · [K9s `enableMouse`](https://github.com/derailed/k9s/blob/master/README.md#k9s-configuration)
- [HIGH | Primary] Textual explicitly says not to rely on tooltips for essential information because keyboard-only users may never see them. [Textual tooltips](https://textual.textualize.io/guide/widgets/#tooltips)
- [HIGH | Primary] Textual terminal screen-reader support remains unresolved in an open first-party issue. Preserve plain-text CLI reports, avoid color-only status, expose copyable details, keep focus order simple, and validate with actual assistive technology before making accessibility claims. [Textual accessibility issue #2425](https://github.com/Textualize/textual/issues/2425)
- [MEDIUM | Primary-derived] Keep textual badges such as `OK`, `DRIFT`, `STUB`, and `?` alongside color. Treat icons as optional decoration because terminal glyph/font support varies.

### Theme and responsive terminal sizing

- [HIGH | Primary] Textual ships multiple light/dark themes, runtime theme switching, semantic success/warning/error colors, and generated foreground colors intended to preserve legibility. [Textual themes](https://textual.textualize.io/guide/design/)
- [HIGH | Primary] Breakpoint classes work on width and height, and Textual's test pilot can start at a specified size or resize during a test. [App breakpoints](https://textual.textualize.io/api/app/#textual.app.App.HORIZONTAL_BREAKPOINTS) · [Textual testing sizes](https://textual.textualize.io/guide/testing/#changing-the-screen-size)
- [HIGH | Primary] K9s supports no-icon mode because terminals differ in character support. [K9s UI configuration](https://github.com/derailed/k9s/blob/master/README.md#k9s-configuration)
- [MEDIUM | Primary-derived] Start with built-in Textual themes and semantic variables. Spend effort on narrow-terminal hierarchy and focus contrast before an Atlas-specific skin.
- [MEDIUM | Primary-derived] Test at minimum 80x24, one narrower supported size, and a wide layout. Define a clear minimum with an actionable message instead of allowing controls to disappear.

### State persistence

- [HIGH | Primary] `platformdirs` distinguishes user configuration from runtime state and returns operating-system-appropriate paths. [platformdirs explanation](https://platformdirs.readthedocs.io/en/latest/explanation.html#choosing-the-right-directory) · [platformdirs API](https://platformdirs.readthedocs.io/en/latest/api.html#user-directories)
- [HIGH | Primary] K9s persists active namespace and view per context; lazygit uses standard OS-specific config paths and supports scoped overrides. Both show the value of restoring context while keeping configuration explicit. [K9s configuration](https://github.com/derailed/k9s/blob/master/README.md#k9s-configuration) · [lazygit user config](https://github.com/jesseduffield/lazygit/blob/master/docs/Config.md?plain=1)
- [MEDIUM | Primary-derived] Atlas should persist only stable preferences: last valid drive, theme, sort key/direction, and perhaps whether detail is visible. Do not restore filter text, marked projects, modal state, or pending plans by default.
- [MEDIUM | Primary-derived] State loading must be best-effort and schema-versioned. Invalid or stale paths should fall back to drive discovery without blocking startup.

### Batch actions

- [HIGH | Primary] K9s separates cursor from marks, supports marking one resource or a range, and clears marks explicitly. VisiData similarly makes selected rows a reusable subset for copy, delete, filter, and other operations. [K9s marks](https://github.com/derailed/k9s/blob/master/README.md#key-bindings) · [VisiData row subsets](https://www.visidata.org/docs/rows/#subset)
- [HIGH | Primary] Current Textual `DataTable` has no native multi-row selection API. A 2026 proposal distinguishing cursor from keyed selection was closed as not planned; an earlier contiguous-range approach did not land. [Textual issue #6586](https://github.com/Textualize/textual/issues/6586)
- [MEDIUM | Primary-derived] If user demand justifies batch work, implement only a thin Atlas selection model: `set[ProjectKey]`, Space toggle, optional range anchor, visible marker column, and aggregate preview. Do not fork or replace `DataTable`.
- [MEDIUM | Primary-derived] Batch mutations need stronger safeguards than single-project work: target count in title and confirmation button, per-project plans, precondition recheck, bounded concurrency, and deterministic partial-failure behavior.

### File opening

- [HIGH | Primary] Textual's `App.open_url` opens a URL in the default web browser; it is not a general desktop file opener. `DirectoryTree` emits selected file/directory paths but leaves opening behavior to the app. [Textual `open_url`](https://textual.textualize.io/api/app/#textual.app.App.open_url) · [DirectoryTree messages](https://textual.textualize.io/widgets/directory_tree/#messages)
- [HIGH | Primary] On Windows, Python `os.startfile(path)` behaves like double-clicking in Explorer and opens a file with its associated application. This matches Atlas's current target. [Python `os.startfile`](https://docs.python.org/3/library/os.html#os.startfile)
- [HIGH | Primary] Textual provides `App.suspend()` for temporarily handing the terminal to an external terminal program. Python recommends argument lists with the subprocess shell disabled by default, avoiding shell parsing of project paths. [Textual `App.suspend`](https://textual.textualize.io/api/app/#textual.app.App.suspend) · [Python subprocess security](https://docs.python.org/3/library/subprocess.html#security-considerations)
- [HIGH | Primary] Lazygit and Yazi distinguish “open in default application” from “edit/open with,” and Yazi makes opener rules operating-system-specific. [lazygit file actions](https://github.com/jesseduffield/lazygit/blob/master/docs/keybindings/Keybindings_en.md#files) · [Yazi opener configuration](https://yazi-rs.github.io/docs/configuration/yazi/#opener)
- [MEDIUM | Primary-derived] Atlas should expose two commands with explicit labels: **Open folder** and **Edit project file**. Validate paths remain inside the selected project, pass paths as one subprocess argument, and show a durable error if no editor is configured.

## Contradictions and hidden variables

- [HIGH | Primary] **Palette vs visible shortcuts:** palettes improve breadth and search; focused footers and `?` help improve immediate discoverability. Hidden variable: action frequency. Keep direct keys for frequent actions and palette entries for the long tail. [Textual palette](https://textual.textualize.io/guide/command_palette/) · [Footer](https://textual.textualize.io/widgets/footer/)
- [HIGH | Primary] **Mouse support vs terminal selection:** Textual supports mouse well, but lazygit documents that capture makes text selection harder and K9s defaults mouse off. Hidden variables: terminal, user preference, and need to copy text. Make every interaction keyboard-complete and avoid custom capture. [Textual mouse input](https://textual.textualize.io/guide/input/#mouse-input) · [lazygit mouse setting](https://github.com/jesseduffield/lazygit/blob/master/docs/Config.md?plain=1)
- [HIGH | Primary] **Rich previews vs shared-drive performance:** file-manager previews are valuable locally, but Yazi advises disabling them on network mounts. Hidden variable: whether file metadata/content is local or placeholder-backed. Atlas should preview report data, not file contents, until the user asks. [Yazi network preview guidance](https://yazi-rs.github.io/docs/tips/#folder-previewer)
- [HIGH | Primary] **Async cancellation vs blocking filesystem APIs:** exclusive workers cancel coroutines, but cannot forcibly stop threads. Hidden variable: API type. Use thread workers for filesystem calls plus cooperative checks and stale-result rejection. [Textual workers](https://textual.textualize.io/guide/workers/#thread-workers)
- [HIGH | Primary] **Undo confidence vs filesystem reality:** lazygit can undo operations represented in Git history but excludes working-tree changes. Hidden variable: authoritative reversible history. Atlas has logs and plans, not a transactional filesystem, so preview and precondition checks outrank a generic undo button. [lazygit undo scope](https://github.com/jesseduffield/lazygit/blob/master/docs/keybindings/Keybindings_en.md#global-keybindings)
- [HIGH | Primary] **Batch speed vs blast radius:** K9s/VisiData prove marks are useful; Textual has no native multi-selection and Atlas mutations affect shared folders. Hidden variables: operation reversibility and target count. Ship marks only after aggregate preview and partial-failure UX exist. [Textual issue #6586](https://github.com/Textualize/textual/issues/6586) · [K9s marks](https://github.com/derailed/k9s/blob/master/README.md#key-bindings)
- [HIGH | Primary] **Screen-oriented power vs screen-reader access:** dense master-detail layouts help sighted expert users but Textual's accessibility status is unresolved. Hidden variable: assistive technology. Preserve line-oriented CLI output and offer plain-text detail export/copy. [Textual accessibility issue #2425](https://github.com/Textualize/textual/issues/2425)
- [HIGH | Primary-local] **Current docs vs declared minimum:** Atlas resolves Textual 8.2.8 locally but declares `textual>=0.80`. Hidden variable: installed framework version. Any use of newer help panels, breakpoints, keymaps, or APIs must either raise the minimum or have compatibility tests.
- [MEDIUM | Primary-derived] **State restoration vs freshness:** restoring last drive/theme helps; restoring filtered or marked rows can hide projects or accidentally preserve batch targets. Persist preferences, not transient intent.

## Survivorship-bias sweep

- [HIGH | Primary] **Command-palette binding migrated:** Textual used `Ctrl+Backslash` before 0.77.0 and now uses `Ctrl+P`. The old binding was difficult or impossible on Swiss/Swedish layouts and over SSH. Do not hard-code punctuation-heavy shortcuts; allow an alternate binding and test Windows terminal layouts. [Textual palette migration note](https://textual.textualize.io/guide/command_palette/#changing-command-palette-key) · [Textual issue #3403](https://github.com/Textualize/textual/issues/3403)
- [HIGH | Primary] **Runtime binding mutation is discouraged:** `App.bind` is documented as potentially private or removable; Textual points to dynamic actions instead. Use static bindings with `check_action`, not ad hoc rebinding. [Textual `App.bind` warning](https://textual.textualize.io/api/app/#textual.app.App.bind)
- [HIGH | Primary] **Native DataTable multi-selection did not land:** an earlier contiguous-range pull request and a broader keyed-selection pull request were superseded by a tracking issue closed as not planned. Keep Atlas's eventual mark model thin and isolated. [Textual issue #6586](https://github.com/Textualize/textual/issues/6586)
- [HIGH | Primary] **Textual screen-reader support remains unresolved:** issue opened in 2023 remains open in 2026, with no assignee, milestone, or implementation. Do not infer accessibility from “text UI.” [Textual issue #2425](https://github.com/Textualize/textual/issues/2425)
- [HIGH | Primary] **Network preloading is a proven negative:** Yazi recommends turning previews/preloads off for network files because they cause downloads. Atlas's Google Drive mount makes this more than a theoretical concern. [Yazi performance guidance](https://yazi-rs.github.io/docs/tips/#make-yazi-even-faster)
- [HIGH | Primary] **Universal undo is not present even in lazygit:** its undo/redo excludes working-tree changes. Build operation-specific inverses only where safety is demonstrable. [lazygit undo limitation](https://github.com/jesseduffield/lazygit/blob/master/docs/keybindings/Keybindings_en.md#global-keybindings)
- [HIGH | Primary] **K9s customization remains churn-prone:** configuration is marked “in flux,” hotkeys “might change,” and custom views “experimental.” For a small Atlas app, user-configurable columns, plugins, and keybinding editors are premature. [K9s configuration](https://github.com/derailed/k9s/blob/master/README.md#k9s-configuration) · [K9s hotkeys](https://github.com/derailed/k9s/blob/master/README.md#hotkey-support) · [K9s custom views](https://github.com/derailed/k9s/blob/master/README.md#custom-views)
- [HIGH | Primary] **Mouse-first interaction carries copying cost:** lazygit's default mouse capture makes terminal text selection require modifiers. Avoid requiring pointer input and keep copy-path/copy-error commands explicit. [lazygit mouse setting](https://github.com/jesseduffield/lazygit/blob/master/docs/Config.md?plain=1)
- [HIGH | Primary] **Shell integration is platform-specific:** Yazi needs shell wrappers to change the parent shell's working directory and OS-specific opener rules. Atlas should open paths, not try to change the launching shell's directory. [Yazi shell wrapper](https://yazi-rs.github.io/docs/quick-start/#shell-wrapper) · [Yazi openers](https://yazi-rs.github.io/docs/configuration/yazi/#opener)

|---|---|---|---|

| Context help | Static homemade key legend | Focus-scoped `Binding`, `Footer`, built-in help panel, `check_action` | Automatically follows focus and action availability. [HIGH | Primary] [Footer](https://textual.textualize.io/widgets/footer/) |

| Spinner/progress visuals | Custom animation loop | Widget `loading`, `LoadingIndicator`, `ProgressBar` | Built-in rendering and lifecycle. [HIGH | Primary] [Loading](https://textual.textualize.io/guide/widgets/#loading-indicator) |

| Filesystem tree | Recursive custom tree widget | `DirectoryTree`, filtered and mounted only on demand | Selection messages, filtering hook, reload support. Avoid eager remote traversal. [HIGH | Primary] [DirectoryTree](https://textual.textualize.io/widgets/directory_tree/) |

| Universal filesystem undo | Generic inverse-command stack | Immutable preview plans, precondition checks, read-only mode, operation log, narrow safe inverses | Mature TUIs limit undo to domains with reliable history. ## Suggested interaction model

- [MEDIUM | Evidence-backed recommendation] **Home:** drive title, filter input when active, project table, selected-project detail, durable status line, contextual footer.
- [MEDIUM | Evidence-backed recommendation] **Navigation:** arrows/j-k move; `/` filter; `Enter` detail; `Esc` back/clear filter; `?` help; `Ctrl+P` palette; `r` refresh.
- [MEDIUM | Evidence-backed recommendation] **Project actions:** `o` open folder; `e` edit project file; `a` add folders; `c` clean; `f` conform. Invalid mutation actions hidden or disabled, not silent.
- [MEDIUM | Evidence-backed recommendation] **Sorting:** click header or palette/menu action; default to severity then natural project name; show direction in header or status.
- [MEDIUM | Evidence-backed recommendation] **Detail:** Overview, Findings, Plan. Folder tree only on demand. No automatic file-content preview.
- [MEDIUM | Evidence-backed recommendation] **Safety:** every destructive or relocating action opens an exact, scrollable preview with target project, path list, counts, conflict behavior, and explicit action label. Batch adds target count and per-project grouping.
- [MEDIUM | Evidence-backed recommendation] **Results:** success toast plus durable summary; partial failure remains visible with retry/copy-log options.
