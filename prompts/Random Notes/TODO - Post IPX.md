**Realie Permission:**

It's a one-line-ish permission request to hello@realie.ai that converts a residual Terms-of-Use ambiguity into written permission. Recommended but explicitly not blocking - the ADR-0019 review already judged the use defensible.



The background: PRD-148 Phase 2 recorded \~14 addresses' worth of real Realie API responses and committed them (PII-scrubbed) as seed fixtures in the private repo. The ToS review (ADR-0019, stamped 2026-07-11 against realie.ai/terms) found §2 grants a license for "internal business purpose" use, and nothing in storage or redistribution clauses is triggered by a private, non-distributed repo copy. The one residual is §7: "Systematically retrieve data ... to create or compile ... a collection, compilation, database, or directory without written permission from us." That clause has no commercial-purpose qualifier, and a frozen 14-address fixture set is arguably a "compilation" - so the email exists to get that written permission on record.



The email therefore needs to state four facts and make one ask:



1\. Who you are - a paying API subscriber (the monthly API tier, not the Bulk Data License).

2\. What you stored - a small, fixed set of API responses (\~14 properties) saved as test fixtures.

3\. The containment facts that keep it inside the §2 license: internal development/testing only, private repository, owner names and person-identifying fields scrubbed at capture, never redistributed, resold, republished, or used in any customer-facing or FCRA-type eligibility decision.

4\. The ask - written confirmation that this use is permitted under your subscription (i.e., §7's compilation clause either doesn't apply or is permitted in writing).
